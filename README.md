# ncm-pm-sync · 网易云私信 → 歌单 自动同步工具

把网易云音乐**私信里分享的歌曲/专辑**自动收进自己的歌单。提供命令行脚本与网页 GUI 两套入口，共用同一套业务逻辑；支持计划预览勾选、真实艺术家标注、三层去重记忆、审计流水。

---

## 核心依赖：API 服务（重要）

本工具**不直接访问**网易服务器，全部数据操作通过开源 API 服务转发官方接口完成。

| 项目 | 地址 |
|---|---|
| **接口服务（当前维护）** | **<https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced>** |
| 本地部署地址 | `http://localhost:3000`（默认） |
| 一键启动 | `npx @neteasecloudmusicapienhanced/api@latest` |

### 依赖的接口清单（名称 · 地址 · 参数）

> 以下接口均由上述服务提供，本工具的核心链路全部依赖它们：

| 接口名称 | 接口地址 | 关键参数 | 用途 |
|---|---|---|---|
| **私信列表** | `/msg/private` | `limit`, `offset` | 拉取私信会话 |
| **私信内容（会话历史）** | `/msg/private/history` | `uid`, `limit`, `before` | 逐会话展开消息流 |
| **最近联系人** | `/msg/recentcontact` | — | 辅助确认会话 |
| **收藏单曲到歌单** | `/playlist/tracks` | `op=add\|del`, `pid`, `tracks`（**必须带 `timestamp`**） | 曲目入库/删除 |
| **专辑内容** | `/album` | `id` | 专辑展开曲目 |
| **歌曲详情** | `/song/detail` | `ids`（≤1000） | 曲名/艺术家批量补查 |
| **歌单全部曲目** | `/playlist/track/all` | `id`, `limit` | 歌单查重 |
| **新建歌单** | `/playlist/create` | `name` | 自动创建目标歌单 |
| **用户歌单** | `/user/playlist` | `uid`, `limit` | 歌单下拉列表 |
| **账号信息** | `/user/account` | — | 登录态校验 |
| **扫码登录** | `/login/qr/key` · `/login/qr/create` · `/login/qr/check` | `key`, `qrimg`, `noCookie` | 二维码登录（800/801/802/803） |

登录后所有请求携带 `?cookie=encodeURIComponent(cookie)`；v4.29.7 起登录态请求**必须带 `timestamp`** 字段。

## 1. 组件与文件说明

| 文件 | 类型 | 功能 |
|---|---|---|
| `ncm_sync.py` | 核心脚本（CLI） | 全部业务逻辑：扫码登录、报文探测、采集计划、入库记账、审计查询、记忆清零。纯 Python 标准库，零第三方依赖 |
| `ncm_gui.py` | 网页 GUI | 本地 Web 界面（默认 `http://127.0.0.1:8765`），直接调用 ncm_sync 的业务函数完成全流程，非命令行套壳 |
| `run_gui.bat` | 启动器 | 一键启动 GUI（自动开浏览器） |
| `run_sync.bat` | 启动器 | 无界面执行一次同步，日志追加到 `sync.log`，供 Windows 任务计划定时调用 |
| `config.example.json` | 配置模板 | 复制为 `config.json` 后修改（GUI 的"保存配置"也会生成/更新它） |
| `预览-spotify风格.html` | 设计稿 | GUI 视觉风格对照稿（静态预览） |

运行后产生的数据文件（均在本目录，**已 .gitignore 不会上传**）：

| 文件 | 作用 | 处理方式 |
|---|---|---|
| `config.json` | 运行配置（歌单、频率、专辑模式等） | GUI 表单读写 / 手工编辑 |
| `cookies.json` | 扫码登录凭证（含 MUSIC_U 等） | 自动生成；**不要外传**；过期后重新 login |
| `state.json` | 去重记忆（已处理消息 ID、已入库曲目 ID） | 自动维护；`reset --yes` 可清空 |
| `sync_history.jsonl` | 审计流水（append-only）：每次入库/跳过/失败的来源与曲目 | GUI ④ 区查看，可下载 |
| `discover_dump.json` | 私信原始报文（探测结果，用于校准解析） | GUI ⑤ 区抓取/下载 |
| `last_plan.json` | 计划缓存（10 分钟内免重扫） | 自动生成 |
| `qr.png` | 登录二维码图片（GUI 直接显示在页面里） | 临时文件 |
| `sync.log` | `run_sync.bat` 的运行日志 | 追加写入 |

### 1.1 核心脚本 ncm_sync.py（CLI 用法）

```bash
python ncm_sync.py login            # 扫码登录（弹出二维码，手机端确认）
python ncm_sync.py discover         # 抓取私信原始报文 → discover_dump.json（校准解析用）
python ncm_sync.py sync             # 正式同步（等价于 GUI 的 采集→全部入库）
python ncm_sync.py sync --dry-run   # 只预览将入库内容，不写歌单
python ncm_sync.py status           # 登录状态、去重记忆计数、审计条数
python ncm_sync.py history -n 20    # 查看审计流水（谁、何时、加了/跳过了什么）
python ncm_sync.py reset --yes      # 清空本地记忆（歌单不动，重新全量判重）
```

业务分层（GUI 复用的两个关键函数）：
- **collect_plan**：只读采集——拉会话列表 → 逐会话展开历史 → 解析分享卡片（曲名/专辑名/艺术家均白嫖自报文）→ 专辑展开曲目 → 生成入库计划（不写歌单、不写状态）
- **commit_plan**：入库记账——按勾选把曲目写入歌单，更新三层记忆与审计流水；**未勾选的分享保持"待处理"**，下次采集仍会出现

### 1.2 网页 GUI ncm_gui.py

```bash
python ncm_gui.py            # 启动并自动打开浏览器（默认 8765 端口）
python ncm_gui.py --no-open  # 只起服务不弹浏览器
python ncm_gui.py --port 8877
```

界面模块（Spotify 设计风格，仅绑定 127.0.0.1）：

| 模块 | 功能 |
|---|---|
| 状态栏 | API 服务连通性、登录账号、目标歌单、记忆计数（红绿状态点） |
| ① 连接与登录 | 填 API 服务地址、测试连接、**页内显示登录二维码**并自动轮询扫码状态 |
| ② 同步配置 | 目标歌单（下拉选自账号真实歌单/手填 ID/自动新建）、轮询条数、请求间隔、专辑入库模式（整张/前 N 首）、是否收分享歌单、专辑曲目倒序入库（保证歌单内正序排列）、云音乐小秘书优先（排最前且排重以其为基准，防专辑被切割） |
| ③ 同步执行 | **采集计划（预览）** → 表格逐条勾选（**勾选未读**一键打钩所有推导未读项；**勾选状态未定**一键打钩所有无法判定已读/未读的条目）→ **入库已勾选 / 全部入库**；显示来源（云音乐小秘书条目自动拼接真实艺术家，如"云音乐小秘书-Eminem"）、专辑/曲目名称、可入库曲目、未读/已读/未定推导标记（默认仅勾选未读，未读排前） |
| ④ 记忆与审计 | 审计流水表（可按入库/跳过/失败筛选）、清空本地记忆（二次确认） |
| ⑤ 报文探测与文件 | 抓取私信报文（JSON 查看器）、打开数据目录、下载数据文件 |
| 运行日志 | 实时滚动（成功绿/失败红/跳过橙），长任务可看进度 |

便捷行为：
- **计划缓存**：10 分钟内重复点「采集计划」直接返回上次结果（秒开），「强制重新采集」才重扫
- 首次全量扫描约 5~10 分钟（防风控限速），日志面板实时可见进度
- 错误以红色提示条弹出，同时写入审计流水，不吞错

## 2. 全流程：起服务、起页面、跑起来

从零到完成一次入库，按顺序走五步：

### 第 1 步：启动 API 服务（保持运行）

```bash
npx @neteasecloudmusicapienhanced/api@latest
```

看到 `Server started successfully @ http://localhost:3000` 即成功。此窗口**不要关**（关了工具就连不上了）。重启电脑后需重新执行本步。

### 第 2 步：启动 GUI 页面（保持运行）

双击 `run_gui.bat`，或：

```bash
python ncm_gui.py
```

浏览器自动打开 `http://127.0.0.1:8765`。页面顶部状态栏显示 **API 服务：正常** 即链路通了（若显示不可用，回第 1 步检查服务是否在跑）。

### 第 3 步：扫码登录

1. 点「**扫码登录**」，页面中间出现圆形二维码
2. 手机网易云音乐 → 扫一扫 → 确认登录
3. 页面状态变为 **登录成功**，顶部状态栏出现你的昵称

cookie 保存在 `cookies.json`，一般可维持数周；失效时状态栏变红，重做本步即可。

### 第 4 步：配置目标歌单

在 ② 区：
1. 点「**刷新**」加载你账号的全部歌单，下拉选中目标歌单（或直接填歌单 ID）
2. 没有合适的就填个新名字（如 `私信收藏`），首次采集时会自动创建
3. 点「**保存配置**」

其余参数保持默认即可；想调整频率/专辑模式时改完再保存。

### 第 5 步：采集 → 勾选 → 入库

1. 点「**采集计划**」——只读扫描私信（首次 5~10 分钟，日志实时滚动；10 分钟内再点秒开）
2. 表格里逐条看清：来源（小秘书条目带真实艺术家）、分享的是专辑/歌曲、将入库多少首、曲目名称
   - 绿色 **待入库** = 会加进歌单的新曲目（默认已勾选）
   - 灰色 **已存在/已忽略** = 自动跳过（重复曲目、MV 等不入库类型）
3. 取消勾选你不想收的条目，点「**入库已勾选**」（或直接「全部入库」）
4. 顶部状态栏记忆计数更新，④ 区审计流水可查每笔来源

之后的日常同步：直接跑 `run_sync.bat`（全自动采集+入库，无预览），或进 GUI 重复第 5 步（有人工把关）。

### 可选：定时自动同步（Windows 任务计划）

```bat
schtasks /create /tn NcmDmSync /tr "D:\WorkBuddy\ncm-pm-sync\run_sync.bat" /sc minute /mo 15
```

每 15 分钟静默同步一次（前提是第 1 步的 API 服务在跑）。删除任务：`schtasks /delete /tn NcmDmSync`。

## 3. 同步机制与去重记忆

**两阶段采集（保证不漏）**：先拉私信会话列表取对方 uid，再逐会话拉历史消息流解析分享卡片——即使分享不是会话里的最新一条也能收到。

**三层去重（判断"哪些已经加过"，不依赖已读状态）**：

| 层 | 载体 | 作用 |
|---|---|---|
| ① 歌单现有曲目 | 入库前实时拉取 | 最权威：歌单里有就不加 |
| ② 处理记忆 | `state.json` | 记住处理过的消息 ID + 入库过的曲目 ID，跨轮次去重；**你手动从歌单删掉的歌不会被自动加回** |
| ③ 审计流水 | `sync_history.jsonl` | 可回查每笔入库的来源私信、时间、曲目 |

**识别规则**：歌曲（`song`）与专辑（`album`，自动展开全部曲目）入库；分享歌单默认忽略（配置可开）；MV 等其它类型识别出来但标注"不入库"；下架资源（404）容错跳过并记审计。同一首歌被多个歌手分享，只收一次。曲名/专辑名/艺术家均直接取自私信报文（零额外请求），缺名时按曲目批量补查（`/song/detail`，100 首/次）。

## 4. 配置项（config.json）

| 字段 | 默认 | 说明 |
|---|---|---|
| `api_base` | `http://localhost:3000` | API 服务地址 |
| `playlist_name` | `私信收藏` | 目标歌单名（找不到会自动创建） |
| `playlist_id` | 空 | 填了 ID 就按 ID，忽略歌单名 |
| `poll_limit` | 30 | 每次拉取的私信会话条数 |
| `max_conversations_per_sync` | 20 | 每轮最多展开多少个会话的历史 |
| `history_limit_per_chat` | 30 | 每个会话扫描的历史消息条数 |
| `request_interval_sec` | 2.0 | API 调用间隔（防风控，勿调太小） |
| `album_mode` | `all` | `all`=整张专辑全收；`first_n`=只收前 N 首 |
| `max_album_tracks` | 20 | `first_n` 模式的 N |
| `also_add_shared_playlist` | false | 私信里分享的歌单是否也批量入库 |
| `album_tracks_reverse` | false | 专辑曲目倒序入库（歌单新曲靠前插入，倒序收才能保证整张专辑在歌单内正序排列） |
| `secretary_first` | true | 云音乐小秘书条目排最前；同轮排重以小秘书为基准（先解析先占位），避免专辑被歌手个人私信里的重复曲目切割 |
| `max_state_ids` | 2000 | 去重记忆保留条数上限 |

## 5. 常见问题

| 现象 | 处理 |
|---|---|
| 状态栏"API 服务：不可用" | 第 1 步的服务没启动或端口不对；`curl http://localhost:3000/login/qr/key` 可验证 |
| 登录后又变"未登录" | cookie 过期，重新扫码登录 |
| 采集很慢（5~10 分钟） | 正常：防风控 2 秒/次调用 + 首次要展开全部专辑。③ 区日志看进度；10 分钟内重进走缓存 |
| 审计里出现"下架 404" | 该专辑已被网易下架，跳过，不影响其它 |
| 有些 MV 没进歌单 | 设计如此：只收歌曲/专辑，MV 显示"不入库"灰标 |
| 同一首歌出现两次分享 | 三层去重保证只收一次，后到的显示"已存在" |
| 想彻底重来 | GUI ④ 区「清空本地记忆」（或 `python ncm_sync.py reset --yes`）；歌单内容不动，重新采集仍会按歌单查重 |
| 频繁报"已有任务在执行" | 上一次采集/入库还没跑完（长任务），等日志出现"计划采集完成"再点 |
